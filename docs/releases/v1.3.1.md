# CreapKeeper v1.3.1 — Updating Shouldn't Depend on Restarting

After adding GitHub-powered updates, I realized there was one part I was making more complicated than it needed to be. I want CreapKeeper to update itself, but if Windows doesn't reopen it automatically, I don't really mind launching it again.

The important thing is that the new version gets installed.

## What changed

- Installing the new executable and reopening the app are now **separate steps**.
- If installing the new version fails, the updater can restore the previous executable.
- If the update succeeds but Windows can't relaunch CreapKeeper, **the newer version stays installed**. You can reopen `CreapKeeper.exe` from its original folder.
- CreapKeeper explains this behavior before it closes to install the update.
- An updater error log is written to `%LOCALAPPDATA%\Counter\updater-error.txt` when the helper encounters an installation or restart error.
- A regression test checks that restart failures are no longer handled as installation failures.

## What stays the same

The database, settings, hotkeys, and LAN dashboard are untouched. The user still approves any update before the executable is downloaded and installed, and SHA-256 verification remains in place.

This is a small fix but an important one. Successfully replacing the executable is what matters; automatically reopening the app is a nice extra.

**Validation:** Automated tests run on Windows/Linux. The actual executable-swap process still requires a real Windows desktop test.
