# CreapKeeper v1.2.0 — Giving Counter a Name

At some point I realized that **Counter** was not exactly a memorable name. The project had also grown quite a bit since that original 2017 idea, so I decided to give it a proper name.

Meet **CreapKeeper**.

The new name keeps the original **Creap** spelling, which has always been part of the inside joke. I am not changing it to *creep*.

## What changed

- The Windows download is now `CreapKeeper.exe`.
- The application title, tray entries, README and messages use CreapKeeper.
- The LAN dashboard has its own name: **The Creap Report**.
- There is a new Python entry point: `python Counter/CreapKeeper.py`.
- The release build, documentation, and compatibility tests were updated.

## Upgrading from Counter v1.1.1

1. **Exit** `Counter.exe` from its system tray menu so it is not still running.
2. Download and open `CreapKeeper.exe`.
3. Your old counts and settings should appear without importing or migrating anything.
4. If LAN viewing stops working, click **Check firewall**. Firewall rules restricted to the old executable path may need attention; port-based rules for TCP 8765 should still apply.

## What I deliberately left alone

The database is still `%LOCALAPPDATA%\Counter\Counter.db` on Windows. I also kept `settings.json`, the `COUNTER_DB_PATH` environment variable, SQLite event types, old Python launchers, and the firewall rule identifier `Counter-LAN-Dashboard-8765`. Renaming the app should not make your data disappear.

The dashboard is still opt-in and read-only; it does not require an external server. Automated tests ran on Windows and Linux, and the standalone executable was built. You should still check the hotkeys, tray and LAN page on your own Windows computer after upgrading.

## Final thoughts

This was mostly a name change, but it was also a good opportunity to see how an app can change identities without breaking old data and settings. That was worth doing on its own.
