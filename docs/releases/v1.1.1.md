# Counter v1.1.1 — Windows Firewall Assistance

When I tested the new LAN page, it worked on the same computer but I could not open it from another machine using either the hostname or IP address. In my case, Windows Firewall was the issue.

Rather than make everyone track that down, I wanted the app to check first and offer to help.

## What changed

When LAN sharing starts, Counter now checks for an applicable **enabled inbound TCP 8765 allow rule**. The check happens in the background, and you can also run it yourself using **Check firewall**.

If there is already a suitable rule, including one you or an IT administrator created, the app leaves it alone. It will not create duplicates just because the rule has a different display name.

If a rule is missing, Counter asks whether to create one. You must approve **both** the app's prompt and Windows UAC. The proposed rule allows:

- TCP port **8765** inbound.
- **Private and Domain** profiles only, not Public.
- Clients on **LocalSubnet** only.

No internet exposure is enabled and existing rules are not rewritten.

## A few notes

The firewall rule remains after you turn off the dashboard or close Counter. That is intentional: the application stops listening, but it does not remove firewall configuration without your knowledge.

To remove only the standard rule that Counter creates, run PowerShell as Administrator:

```powershell
Remove-NetFirewallRule -Name "Counter-LAN-Dashboard-8765"
```

If coworkers still cannot reach the dashboard, test from their computer:

```powershell
Test-NetConnection COUNTER-PC-IP -Port 8765
```

A different VLAN may be outside `LocalSubnet`, and managed security policies may override local rules. The app can check rule configuration, but it cannot guarantee another device can reach the port.

Existing counts, hotkeys, tray and dashboard behavior are preserved. The UAC interaction is mocked in automated tests, so the final approval flow still needs checking on a Windows desktop.
