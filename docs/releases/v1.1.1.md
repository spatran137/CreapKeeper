# Counter v1.1.1 — Windows Firewall Assistance

The LAN dashboard works locally but Windows Firewall can block coworkers from connecting. This patch automates the **check** while keeping firewall modifications opt-in.

## Improvements

- **Checks existing Windows Firewall rules** on first enabling the LAN server and when the sharing setting is restored after launch. It also supports a manual **Check firewall** button.
- Recognizes compatible user-created and IT-created enabled inbound **allow** rules for TCP 8765, including a manually created **Creap Counter Dashboard** rule. If one is found, it makes **no changes** and does **not** request elevation.
- When no suitable rule is found, offers to create exactly one **Counter LAN Dashboard** rule. The user must approve both the in-app confirmation and Windows UAC prompt.
- The created rule is restricted to **Private/Domain network profiles**, **TCP 8765**, and **LocalSubnet** remote addresses. No Public or internet exposure.
- Uses an unprivileged PowerShell check on a worker thread, so the Counter interface stays responsive.
- Checks the rule after the elevation attempt instead of falsely claiming success on UAC launch.
- Adds troubleshooting and removal instructions to README.
- Keeps existing SQLite history, hotkeys, tray, and LAN dashboard unchanged.

## Notes

The rule persists after the dashboard is disabled; Counter never deletes or changes an existing rule. If installed by Counter, an administrator may remove it with:

    Remove-NetFirewallRule -Name "Counter-LAN-Dashboard-8765"

On managed Windows machines, organizational firewall policy may block local rules. A rule allowing only `LocalSubnet` may not permit another VLAN. Use `Test-NetConnection COUNTER-PC-IP -Port 8765` from the other machine to confirm connectivity.

This release does not request administrative access unless you explicitly approve creating the missing rule. Automated tests mock Windows elevation; final UAC and firewall checks require a real Windows PC.
